# AGENTS.md — IndietroTuttaBackend (Express + Turso + Leaflet)

Web backend + live map + boat panels + OTA host for ESP32 devices.
Prod: `https://indietrotutta.onrender.com`. Local: `node server.js` → `:3000`.

## Stack / entry

- `server.js`: cors + `express.json()` + `public/` static, mounts `gps,health,devices`, then `initDb().then(listen)`. Falls back to in-memory mode if no `TURSO_DATABASE_URL`.
- Deps: `@libsql/client ^0.17.4`, `express ^5.2.1`, `cors`, `dotenv`, `node-fetch`, `nodemon`.
- `config.js` only exports PORT. `.env` (gitignored, required): `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, `REDPLOY_HOOK_URL` (note typo REDPLOY). Render env mirrors it.
- `store/db.js`: `getClient()` / `initDb()` creates `devices, gps_points, templates, sessions, session_boats, runs, signals` (+ gps indexes; `devices` migrates `firmware`/`boat`/`ip` TEXT + `mock` INTEGER; `sessions` migrates `windSpeed` REAL). No row cap. Connection test `SELECT 1` throws on bad token.
- (Race program live: `templates` (renamed from `courses`) → `sessions` → scripted `sim` → device race screen. `races` dropped. See root AGENTS.md.)

## Stores (all have in-memory Map fallback when DB missing)

- `deviceStore.js`: `upsertDevice(deviceId,{username,firmware,ip})` preserves `firstSeen` (captures LAN `ip` from heartbeats); `setDeviceMock(deviceId,on)` records assumed mock-GPS state without touching `lastSeen` (no fake live). Username `/^[A-Za-z0-9 ._-]{1,32}$/`, firmware `/^[A-Za-z0-9._-]{1,16}$/`, boat `/^[A-Za-z0-9 ._-]{1,64}$/` (bad values keep old). `renameDevice(deviceId,{username,boat})` edits info without touching `lastSeen` (no fake live). `getDevices()` adds `status: live<90s / idle<10m / offline`. `deleteDevice` also deletes its gps_points.
- `gpsStore.js`: `addPoint({deviceId,username,lat,lon,speed,course,altitude,sats,timestamp,receivedAt})`. `getPoints({date,deviceId,start,end})` — `start/end` ISO range takes precedence over `date` (YYYY-MM-DD on `substr(timestamp,1,10)`), `ORDER BY id ASC`. `getLatestPoint(deviceId?)`, `getPointCount()`. (Waypoints/flagged are GONE: no `flagged`/`uid` columns — dropped by a guarded migration in `initDb`.)

## Routes (every new route needs `bruno/*.bru`)

- `GET|POST /health` — heartbeat: `upsertDevice` from `DeviceId`/`Username`/`Firmware-Version` headers (POST also body incl. `fw`), returns `{status, storedPoints, deviceId, heartbeat, serverTime}`. GET also piggybacks `session` (assigned scheduled/live session: id/mode/status/startTime/startOffsetSec/courseVersion/windDir/windSpeed/marks/startLine/finishLine/signals; null when unassigned) and `wind` `{dir,speed}` — venue wind from the boat's last stored point via the `store/wind.js` chain, stale-while-revalidate per device (10-min TTL / >2 km drift / first poll; session wind wins on the device).
- `gps.js`: `POST /gps` (validate lat/lon numbers, store + upsert device; `simulated` uploads skip Turso into an ephemeral single-point slot; also keeps `devices.mock` in sync from the `simulated` field — transition-only writes, so the mock flag is reliable without a device change), `GET /gps/sim-live?deviceId=` (latest sim point only, no history — refresh picks up upcoming fixes exclusively), `GET /gps?date=&deviceId=` or `?start=&end=`, `GET /gps/latest?deviceId=`, `GET /gps/count`, `GET /gps/days?deviceId=` (days with data + counts for per-boat calendar). No flagged/waypoint routes (removed 2026-10-09).
- `templates.js`: `GET /templates/presets` (5 wind-frame presets, no DB), `GET /templates`, `POST /templates` (`{name,desc?,marks[,startLine,finishLine]}` or `{name,template:presetKey}`), `GET/PUT/DELETE /templates/:id` (PUT bumps `version`). Optional line segments `{ax,ay,bx,by,square?,bias?}` (≥5m, square-to-wind default); `finishLine` may be `{sameAs:"start"}`.
- `sessions.js`: sessions encapsulate templates (frozen snapshot, never linked). Status is inferred on read (abandoned sticks; boat-less sessions stay `scheduled` — a session can NEVER be live with 0 boats; finished when every boat uploaded a run; live once the gun passes; else scheduled) — `PUT` accepts only `abandoned` (or `scheduled` to re-open). **One active session per boat:** `addBoat`/`repeatSession` reject (409, message names the blocking session) when the boat is already in another scheduled/live session. **Auto-sim:** adding a boat that is currently `mock` auto-creates its scripted run (`store/sim.createRun`). `windSpeed` (kn, optional) is stored and pushed via health. `GET /sessions[?date=]`, `POST /sessions` (`{templateId}` or `{snapshot:{marks,startLine?,finishLine?}}` + placement → resolved marks; stamps `templateVersion`), `GET/PUT/DELETE /sessions/:id` (geometry edits re-resolve + bump `courseVersion`), `POST /sessions/:id/repeat` (same frozen shape onto a new day, boats carried over), `POST/DELETE /sessions/:id/boats[/:deviceId]` (participants + pursuit `startOffsetSec`). Run uploads: `POST /sessions/:id/runs` (device finish log `{deviceId,startEpoch,finishEpoch?,splits?,events?,result?}`, re-upload replaces), `GET /sessions/:id/runs` (results, finished first). Committee: `POST /sessions/:id/signals` (`{kind: OCS|DSQ|DNF|RET|SCP|RECALL|ABANDON, deviceId?, detail?}`), `GET /sessions/:id/signals` (log, oldest first).
- `wind.js`: `GET /wind?lat=&lon=[&provider=auto|wu|wc|om]` — suggest-only venue wind (WU PWS `WU_API_KEY` → Weathercloud unofficial → Open-Meteo model), 10-min cache keyed by `lat,lon,provider`; `provider` forces a single source (502 `no data from provider 'x'` when it has none, 400 on an unknown name); caller freezes value into session.
- `sim.js` (in-memory test rig, lost on restart): `POST /sim/runs {sessionId, deviceId?, speedKn?, startInSec?}` compiles a 1Hz scripted route (hold → gun cross → mark/gate centers → finish, seeded noise; default 10 kn), `GET /sim/next?deviceId=` wall-clock delivery, `GET /sim/runs[?sessionId=]`, `DELETE /sim/runs/:id`, `GET /sim/wander?deviceId=` server-driven wander fix (viewport anchor when pushed, else free random walk from last position; 404 with neither), `POST /sim/anchor {lat,lon}` sets the viewport anchor.
- `devices.js` (+ `/boats` alias): `GET /devices`, `GET /boats`, `PUT /devices/:id` / `PUT /boats/:id` rename `{username, boat}` (no heartbeat side effects), `POST /devices/:id/mock` / `POST /boats/:id/mock` `{on:bool}` (proxies to the device portal `/mock` over LAN via stored `ip`, then records `mock`; 409 no known ip, 502 portal unreachable), `DELETE /devices/:id` (+ `/boats/:id`).

## Frontend (`public/`)

- `index.html` + `app.js` + `style.css`, Leaflet 1.9.4 CDN. Topbar: Boats/Wind/Timeline/Sessions/Course/New session/Settings toggles, Live button + preset (today/yesterday/thisWeek/custom) + datetime pickers + recenter.
- Pane chrome is uniform: every floating pane (boats, wind, course, sessions, session detail, new session, edit course, settings, per-boat) uses the same light-gray `#e5e7eb` header bar with one large `.pane-close` × (`h4` rule near `#device-panel h4`; boat pane icons use `.pane-btn` + `.pane-actions`, and must stay `<span>` — `makePanelDraggable` excludes header drags via `h4 span`). Panel drag excludes header buttons; the boat-pane icons are the exception by design.
- Settings pane: `windProvider` (`auto|wu|wc|om`, sent to `/wind`) + `windRefreshMin` (5/10/20/30/0=off) — the single source of truth for wind auto-refresh; the wind pane ↻ is a one-off refresh only (the old AUTO toggle is gone). Both prefs live in the UI prefs blob, so they must be declared before `loadUI()` runs.
- Map: polyline tracks, per-boat colored stripes, no-auto-pan (recenter on demand), hover 100m dots, click-to-jump. Clicking a boat (marker, track, or the **live-sim arrow**) opens its panel: mock boats never reach Turso (`simulated` uploads go to the ephemeral slot), so `findNearestPoint`/`currentPointForBoat` also consider `liveSimLatest(id)` — Turso's newest fix for a mock boat can be days old and km away.
- Boat panels (Leaflet controls, draggable): Speed/Course/Time + Boat make-model, header icons ⌖ (center map, keeps zoom) + ⓘ (info modal) + ×. Info modal: read-only Device/Status/Firmware/Last/First seen + editable Boat name + Make/model → `PUT /boats/:id`, list + panels refresh.
- Boats list: filter, status dots + firmware (`v1.0.x` after lastSeen when reported), 📅 per-row sailing-days calendar (active days in boat color → click sets custom day range).
- Races menu (topbar dropdown): Templates panel (5 presets + yours + blank → builder) and Sessions panel (create + committee: start +5:00/postpone/custom start, status, boats + pursuit offsets, repeat onto new day, delete). Panels draggable, positions persisted, auto-cascade on overlap. The **session-detail** pane only ever shows a selected session: `selectedSessionId` is NOT persisted, so `loadSessions()` drops it when the session vanished (deleted via API) and hides a restored-but-empty pane at boot — otherwise a ghost id re-opens a blank pane forever.
- Builder (right panel, map stays visible): templates only. Click-to-drop + draggable marks (type/radius/order, side on roundings only), whole-course Move drag, bottom-left wind dial + `/wind` suggest, scale, lines list (define/drag ends/move, same-as, bias/square), gate auto-pairing + pile badges, live dashed route + naked meter labels (toggle). Drafts in `localStorage`.
- Playback: play/rewind/speed 1–20x, timeline with per-boat tracks + speed overlay, cursor follows nearest real point, live hides timeline.
- `public/ota/latest.txt + firmware.bin` — written by device `make dist`, served static. `favicon.svg` boat icon.

## Bruno / verify / deploy

- `bruno/` mirrors routes: `health/ gps/ devices/` (incl. `devices-rename.bru`, `devices-mock.bru`), `templates/`, `sessions/` (incl. snapshot + repeat + `add-boat-conflict.bru`), `sim/` (incl. `wander.bru`), `wind/` + `environments/local.bru (:3000)` + `production.bru (onrender)`. Rule: new endpoint → new `.bru`, test both envs.
- Local check: `node server.js` → `curl localhost:3000/health /devices /boats /gps?date=YYYY-MM-DD`; removed routes return 404 (`/courses/*`, `/races`).
- Deploy (`sd`): commit + push `main`, then `POST $REDPLOY_HOOK_URL` (push alone does NOT redeploy), verify `/devices`. OTA publish comes from device repo `make dist` which commits firmware into `public/ota/` here.
- No auth anywhere — identity is `DeviceId` MAC header. Keep validation + username whitelist in sync with firmware.
- **Destructive schema changes: never drop a column while the OLD build is still live.**
  2026-10-09: dropping `gps_points.flagged` locally killed prod (`SQL_INPUT_ERROR: no such
  column: flagged` at `store/db.js:94`) because the deployed build still selected it — every
  DB-backed route 500'd until `sd` redeployed the new code. Safe order: (1) deploy code that
  stops using the column, (2) drop it in a later deploy (or keep it one release). Local
  `:3000` shares the LIVE Turso DB, so a local migration IS a prod migration.
